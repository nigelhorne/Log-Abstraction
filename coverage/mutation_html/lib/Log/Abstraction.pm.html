 2066: =head2 CSV file logging for BI import
 2067: 
 2068: The code-reference backend gives you full control over the output format.
 2069: The example below writes every message at C<trace> level and above as a
 2070: CSV row to a file, producing output that can be loaded directly into a
 2071: spreadsheet or BI tool (Tableau, Power BI, Metabase, etc.).
 2072: 
 2073: Each row contains: C<timestamp>, C<level>, C<class>, C<file>, C<line>, C<message>.
 2074: 
 2075:   use Log::Abstraction;
 2076: 
 2077:   my $csv_file = 'app_events.csv';
 2078: 
 2079:   # Write the header row once (skip if the file already exists and has data).
 2080:   unless (-s $csv_file) {
 2081:       open my $fh, '>', $csv_file or die "Cannot open $csv_file: $!";
 2082:       print $fh qq{timestamp,level,class,file,line,message\n};
 2083:       close $fh;
 2084:   }
 2085: 
 2086:   # Helper: quote a single CSV field (escapes embedded double-quotes).
 2087:   my $csv_field = sub {
 2088:       my $v = defined $_[0] ? $_[0] : '';
 2089:       $v =~ s/"/""/g;
 2090:       return qq{"$v"};
 2091:   };
 2092:

 2094:       level  => 'trace',        # capture everything from trace upwards
 2095:       logger => sub {
 2096:           my $args = $_[0];
 2097: 
 2098:           my $timestamp = POSIX::strftime('%Y-%m-%dT%H:%M:%SZ', gmtime);
 2099:           my $message  = join(' ', @{ $args->{message} // [] });
 2100: 
 2101:           open my $fh, '>>', $csv_file or return;
 2102:           print $fh join(',',
 2103:               $csv_field->($timestamp),
 2104:               $csv_field->($args->{level}),
 2105:               $csv_field->($args->{class}),
 2106:               $csv_field->($args->{file}),
 2107:               $csv_field->($args->{line}),
 2108:               $csv_field->($message),
 2109:           ), "\n";

 2111:       },
 2112:   );

 2115:   $logger->info('user logged in', { user => 'alice' });

 2119: 
 2120:   timestamp,level,class,file,line,message
 2121:   "2026-05-27T14:00:00Z","trace","Log::Abstraction","app.pl","42","application started"
 2122:   "2026-05-27T14:00:01Z","info","Log::Abstraction","app.pl","43","user logged in"

 2129: C<file> and C<line> point into the module rather than the calling script.

 2161: =head1 LIMITATIONS
 2162: 
 2163: =over 4
 2164: 
 2165: =item B<Syslog hash mutation>
 2166: 
 2167: The C<syslog> sub-hash passed to C<new()> is mutated in-place on the first
 2168: log call: C<facility> and C<level> are temporarily removed before
 2169: C<setlogsock()> is called, then restored; C<server> is permanently renamed
 2170: to C<host>.  Sharing a syslog hashref between two C<Log::Abstraction>
 2171: instances is not supported and produces undefined behaviour on the second
 2172: instance.
 2173: 
 2174: =item B<trace is the same threshold as debug>
 2175: 
 2176: syslog has no priority below debug, so C<trace> and C<debug> share one
 2177: threshold: a logger at C<debug> level also emits C<trace> messages, and
 2178: C<trace> can't be filtered separately.
 2179: 
 2180: =item B<Unbounded message history by default>
 2181: 
 2182: Every logged message is kept in the history returned by L</messages>.  In a
 2183: long-running process (a daemon, or under mod_perl) set C<max_messages> to
 2184: stop it growing without bound.
 2185: 
 2186: =item B<syslog connection is shared>
 2187: 
 2188: C<openlog()> and C<closelog()> act on the whole process, so every instance
 2189: logging to syslog shares one connection, opened with the C<script_name> of
 2190: the first.  It is closed when the last such instance is destroyed.
 2191: 
 2192: =item B<No structured log fields>
 2193: 
 2194: All backends except the CODE-ref backend reduce the message to a flat string.
 2195: To log structured key/value pairs, use a CODE-ref backend that formats the
 2196: data itself.
 2197: 
 2198: =item B<Single-threaded email throttle>
 2199: 
 2200: The C<min_interval> throttle for the C<sendmail> backend and the
 2201: C<_syslog_opened> first-open flag are stored on the object without mutex
 2202: protection.  Under Perl ithreads or other concurrency models, objects shared
 2203: between threads are not safe.
 2204: 
 2205: =item B<OpenTelemetry not yet supported>
 2206: 
 2207: The OTel Logs SDK for Perl is incomplete; see the TODO block at the top of
 2208: F<lib/Log/Abstraction.pm> for a full status report and the list of blockers.
 2209: Monitor L<https://metacpan.org/pod/OpenTelemetry::SDK> for progress.
 2210: 
 2211: =item B<Log::Log4perl is a de-facto required dependency>
 2212: 
 2213: When no C<logger>, C<file>, or C<array> backend is configured, C<new()>
 2214: loads L<Log::Log4perl> and uses it as the default backend.  Although listed
 2215: as an optional runtime dependency, it is required in that default-backend
 2216: path.
