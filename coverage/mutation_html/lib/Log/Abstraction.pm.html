  235: =head1 SYNOPSIS
  236: 
  237:   use Log::Abstraction;
  238: 
  239:   my $logger = Log::Abstraction->new(logger => 'logfile.log');
  240: 
  241:   $logger->debug('This is a debug message');
  242:   $logger->info('This is an info message');
  243:   $logger->notice('This is a notice message');
  244:   $logger->trace('This is a trace message');
  245:   $logger->warn({ warning => 'This is a warning message' });
  246: 
  247:   # Structured fields
  248:   $logger->info('User logged in', { user_id => 42 });
  249: 
  250: =head1 DESCRIPTION
  251: 
  252: The C<Log::Abstraction> class provides a flexible logging layer on top of
  253: different types of loggers, including code references, arrays, file paths,
  254: and objects.  It also supports logging to syslog if configured.
  255: 
  256: =head2 Unicode
  257: 
  258: Messages may be character strings containing any Unicode text.  The file,
  259: fd and scalar-path backends write character strings as UTF-8 (unless an
  260: C<fd> handle already has a C<:utf8> or C<:encoding> layer, in which case the
  261: handle does the encoding), and C<format =E<gt> 'json'> output is UTF-8 too.
  262: journald fields are sent as UTF-8.  Byte strings are written unchanged.
  263: 
  264: =head2 Structured fields
  265: 
  266: Every logging method accepts a hash reference of structured fields after
  267: the message:
  268: 
  269:   $logger->info('User logged in', { user_id => 42, ip => $ip });
  270:   $logger->warn('Slow query', { ms => 1250 });
  271: 
  272: A hash reference is taken as fields only when it is the last of two or more
  273: arguments, so C<warn({ warning =E<gt> ... })> keeps its meaning, and a lone
  274: hash reference is still a message.  An empty hash reference is ignored.  The
  275: fields are copied, so changing the hash afterwards doesn't change what was
  276: logged.  They are kept out of the message and go to each backend as follows:
  277: 
  278: =over 4
  279: 
  280: =item * L</messages>, C<array> and an ARRAY C<logger> -- a C<fields> key in
  281: the entry, alongside C<level> and C<message>.
  282: 
  283: =item * a CODE C<logger> -- a C<fields> key in the hashref it is called with.
  284: 
  285: =item * C<format =E<gt> 'json'> -- a nested C<fields> object.  Objects are
  286: stringified; other references are kept as JSON data.
  287: 
  288: =item * C<journald> -- journal fields.  Each name is upper-cased, characters
  289: other than C<A-Z>, C<0-9> and C<_> become C<_>, leading underscores are
  290: removed and it is cut to 64 characters; a field left with no name is
  291: dropped.  Fields override the extra keys in the C<journald> hash, but never
  292: C<MESSAGE>, C<PRIORITY> or C<SYSLOG_IDENTIFIER>.
  293: 
  294: =item * text formats (C<file>, C<fd>, a scalar C<logger>), C<syslog>,
  295: C<sendmail> and object loggers -- appended to the message as logfmt-style
  296: C<key=value> pairs in key order, e.g. C<User logged in ip=10.0.0.1 user_id=42>.
  297: Characters other than C<[\w.-]> in a key become C<_>.  A value that is empty
  298: or contains white space, C<">, C<=> or C<\> is double-quoted, with C<"> and
  299: C<\> escaped and control characters written as C<\n>, C<\r>, C<\t> or
  300: C<\xNN>.  Objects are stringified and other references written as JSON.  An
  301: object logger is passed the pairs as an extra argument after the message.
  302: 
  303: =back
  304: 
  305: When logging through L<Log::Any>, a hash reference at the end of the call,
  306: together with the proxy's C<context>, arrives here as fields; see
  307: L<Log::Any::Adapter::Abstraction/structured>.
  308: 
  309: =head2 File rotation
  310: 
  311: Log files written by path (a scalar C<logger>, a C<file> key in a C<logger>
  312: hash, and the top-level C<file>) can be rotated by size, by time, or both:
  313: 
  314:   my $log = Log::Abstraction->new(
  315:       file            => '/var/log/myapp.log',
  316:       rotate_size     => '10M',
  317:       rotate_interval => 'daily',
  318:       rotate_keep     => 7,
  319:   );
  320: 
  321: Before each write the file is checked, and if it is due it is renamed to
  322: F<myapp.log.1>, the old F<.1> to F<.2> and so on, the oldest beyond
  323: C<rotate_keep> being deleted; the line then goes to a new F<myapp.log>.  A
  324: rotation that fails (e.g. for lack of permission) is ignored, and the line is
  325: still written.  File handles passed as C<fd> aren't rotated.
  326: 
  327: Rotation isn't coordinated between processes: if several processes log to the
  328: same file, use B<logrotate> instead.
  329: 
  330: =head3 logrotate
  331: 
  332: The file is opened, appended to and closed for every message, never held
  333: open, so B<logrotate>'s default (rename the file and let the application
  334: create a new one) works without C<copytruncate>, and without sending the
  335: process a C<SIGHUP>: the next message is written to the new file.

  354: 
  355: =over 4
  356: 
  357: =item * C<carp_on_warn>

  362: =item * C<croak_on_error>

  364: If set to 1, and no C<logger> is given, call C<Carp::croak> on C<error()>.
  365: 
  366: =item * C<config_file>
  367: 
  368: Path to a configuration file (YAML, XML, INI, etc.) whose contents are
  369: merged with the constructor arguments.  On non-Windows systems the class

  371: C<"Log::Abstraction::">.  For example:
  372: 
  373:   export Log::Abstraction::script_name=foo
  374: 
  375: =item * C<ctx>
  376: 
  377: Arbitrary context value passed through to CODE-ref logger callbacks as
  378: C<$args-E<gt>{ctx}>.
  379: 
  380: =item * C<format>
  381: 
  382: Format string for file/fd backends.  Tokens expanded at log time:
  383: 
  384:   %callstack%   caller file and line number
  385:   %class%       blessed class of the logger object
  386:   %level%       upper-cased level name
  387:   %message%     the joined log message
  388:   %timestamp%   the time of the call; YYYY-MM-DD HH:MM:SS local time by
  389:                 default (see timestamp_format, timestamp_precision and utc)
  390:   %env_FOO%     value of $ENV{FOO}, or empty string if unset
  391: 
  392: Tokens are only expanded in the format string itself, never in the text
  393: of the message.  Each line break in a message is followed by a tab, so a
  394: continuation line can't be mistaken for a new log entry.
  395: 
  396: The special value C<"json"> (not a format string but a magic keyword) switches
  397: all file and fd backends to emit one compact JSON object per log line:
  398: 
  399:   {"timestamp":"...","level":"info","message":"...","file":"...","line":42}
  400: 
  401: This format is compatible with log aggregators such as journald, Loki,
  402: Elasticsearch, and Splunk.  C<class> is included when the logger is a subclass
  403: of C<Log::Abstraction>, and C<fields> when the call has L</Structured fields>.
  404: Keys are emitted in sorted order.
  405: 
  406: B<Security note:> because C<format> may contain C<%env_*%> tokens, avoid
  407: granting untrusted sources write access to config files that set this key.
  408: 
  409: =item * C<level>
  410: 
  411: Minimum level at which to emit log entries.  Defaults to C<"warning">.
  412: Valid values (case-insensitive): C<trace>, C<debug>, C<info>/C<informational>,
  413: C<notice>, C<warn>/C<warning>, C<error>/C<err>, C<crit>/C<critical>/C<fatal>,
  414: C<alert>, C<emerg>/C<emergency>/C<panic>.  C<trace> and C<debug> are the same
  415: threshold (see L</LIMITATIONS>).
  416: 
  417: =item * C<max_messages>
  418: 
  419: The most entries to keep in the in-memory history returned by
  420: L</messages>; when it is full, the oldest entry is discarded.  Must be a
  421: non-negative integer.  Unlimited by default, which in a long-running process
  422: means the history grows without bound.
  423: 
  424: =item * C<logger>
  425: 
  426: One of:
  427: 
  428: =over 4
  429: 
  430: =item * A code reference -- called with a hashref C<{ class, file, line, level, message, ctx, fields }>
  431: (C<ctx> and C<fields> only when there are any)
  432: 
  433: =item * An object -- method matching the level name is called on it
  434: 
  435: =item * A hash reference -- may contain C<file>, C<array>, C<fd>, C<syslog>, C<journald>, and/or C<sendmail> keys
  436: 
  437: =item * An array reference -- C<{ level, message }> hashrefs are pushed onto it, with a
  438: C<fields> key when the call has L</Structured fields>
  439: 
  440: =item * A scalar string -- treated as a file path to append to
  441: 
  442: =back
  443: 
  444: When not supplied, L<Log::Log4perl> is initialised as the default backend.
  445: 
  446: The C<sendmail> sub-hash supports:
  447: C<host>, C<port>, C<to>, C<from>, C<subject>, C<level>, C<min_interval>.
  448: C<to> is required.  C<level> may be a level name or a syslog number (0-7);
  449: without it, every message is emailed.
  450: At most one email is sent per C<min_interval> seconds per instance.  If
  451: delivery fails, C<Carp::carp> is called and the other backends still receive
  452: the message.
  453: 
  454: The C<syslog> sub-hash supports:
  455: 
  456: =over 4
  457: 
  458: =item * C<facility> -- the syslog facility (default: C<local0>)
  459: 
  460: =item * C<level> -- only messages at this level or more severe are sent; a level name or a syslog number (0-7)
  461: 
  462: =item * C<host> (or its alias C<server>), and any other L<Sys::Syslog/setlogsock> option -- passed to C<setlogsock()>
  463: 
  464: =back
  465: 
  466: The C<journald> sub-hash sends each message as a single datagram to the
  467: systemd journal using the journald native protocol.  Supported keys:
  468: 
  469: =over 4
  470: 
  471: =item * C<socket> -- path to the journald socket (default: F</run/systemd/journal/socket>)
  472: 
  473: =item * C<identifier> -- value for the C<SYSLOG_IDENTIFIER> field (default: basename of C<$0>)
  474: 
  475: =item * any other key -- included verbatim as an uppercase journald field name.
  476: The upper-cased name must contain only C<A-Z>, C<0-9> and C<_>, and must not
  477: start with C<_>; C<new()> croaks otherwise.
  478: 
  479: =back
  480: 
  481: The C<PRIORITY> field is set automatically from the log level (0=emerg...7=debug).
  482: A message too large for one datagram (about 200KB) is truncated and

 2835: =head1 LIMITATIONS
 2836: 
 2837: =over 4
 2838: 
 2839: =item B<Syslog hash mutation>
 2840: 
 2841: The C<syslog> sub-hash passed to C<new()> is mutated in-place on the first
 2842: log call: C<facility> and C<level> are temporarily removed before
 2843: C<setlogsock()> is called, then restored; C<server> is permanently renamed
 2844: to C<host>.  Sharing a syslog hashref between two C<Log::Abstraction>
 2845: instances is not supported and produces undefined behaviour on the second
 2846: instance.
 2847: 
 2848: =item B<trace is the same threshold as debug>
 2849: 
 2850: syslog has no priority below debug, so C<trace> and C<debug> share one
 2851: threshold: a logger at C<debug> level also emits C<trace> messages, and
 2852: C<trace> can't be filtered separately.
 2853: 
 2854: =item B<Unbounded message history by default>
 2855: 
 2856: Every logged message is kept in the history returned by L</messages>.  In a
 2857: long-running process (a daemon, or under mod_perl) set C<max_messages> to
 2858: stop it growing without bound.
 2859: 
 2860: =item B<syslog connection is shared>
 2861: 
 2862: C<openlog()> and C<closelog()> act on the whole process, so every instance
 2863: logging to syslog shares one connection, opened with the C<script_name> of
 2864: the first.  It is closed when the last such instance is destroyed.
 2865: 
 2866: =item B<Structured fields are text in most backends>
 2867: 
 2868: Only the history, array, CODE-ref, JSON and journald backends keep
 2869: L</Structured fields> as data.  Text formats, syslog, email and object
 2870: loggers get them as C<key=value> text appended to the message, and a custom
 2871: C<format> has no token for them on their own.
 2872: 
 2873: =item B<Single-threaded email throttle>
 2874: 
 2875: The C<min_interval> throttle for the C<sendmail> backend and the
 2876: C<_syslog_opened> first-open flag are stored on the object without mutex
 2877: protection.  Under Perl ithreads or other concurrency models, objects shared
 2878: between threads are not safe.
 2879: 
 2880: =item B<OpenTelemetry not yet supported>
 2881: 
 2882: The OTel Logs SDK for Perl is incomplete; see the TODO block at the top of
 2883: F<lib/Log/Abstraction.pm> for a full status report and the list of blockers.
 2884: Monitor L<https://metacpan.org/pod/OpenTelemetry::SDK> for progress.
 2885: 
 2886: =item B<Log::Log4perl is a de-facto required dependency>
 2887: 
 2888: When no C<logger>, C<file>, or C<array> backend is configured, C<new()>
 2889: loads L<Log::Log4perl> and uses it as the default backend.  Although listed
 2890: as an optional runtime dependency, it is required in that default-backend
 2891: path.
