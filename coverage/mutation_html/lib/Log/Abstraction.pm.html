 1989: 
 1990: =head2 CSV file logging for BI import
 1991: 
 1992: The code-reference backend gives you full control over the output format.
 1993: The example below writes every message at C<trace> level and above as a
 1994: CSV row to a file, producing output that can be loaded directly into a
 1995: spreadsheet or BI tool (Tableau, Power BI, Metabase, etc.).
 1996: 
 1997: Each row contains: C<timestamp>, C<level>, C<class>, C<file>, C<line>, C<message>.
 1998: 
 1999:   use Log::Abstraction;
 2000: 
 2001:   my $csv_file = 'app_events.csv';
 2002: 
 2003:   # Write the header row once (skip if the file already exists and has data).
 2004:   unless (-s $csv_file) {
 2005:       open my $fh, '>', $csv_file or die "Cannot open $csv_file: $!";
 2006:       print $fh qq{timestamp,level,class,file,line,message\n};
 2007:       close $fh;
 2008:   }
 2009: 
 2010:   # Helper: quote a single CSV field (escapes embedded double-quotes).
 2011:   my $csv_field = sub {
 2012:       my $v = defined $_[0] ? $_[0] : '';
 2013:       $v =~ s/"/""/g;
 2014:       return qq{"$v"};
 2015:   };
 2016: 
 2017:   my $logger = Log::Abstraction->new(
 2018:       level  => 'trace',        # capture everything from trace upwards
 2019:       logger => sub {
 2020:           my $args = $_[0];
 2021: 
 2022:           my $timestamp = POSIX::strftime('%Y-%m-%dT%H:%M:%SZ', gmtime);
 2023:           my $message  = join(' ', @{ $args->{message} // [] });
 2024: 
 2025:           open my $fh, '>>', $csv_file or return;
 2026:           print $fh join(',',
 2027:               $csv_field->($timestamp),
 2028:               $csv_field->($args->{level}),
 2029:               $csv_field->($args->{class}),
 2030:               $csv_field->($args->{file}),
 2031:               $csv_field->($args->{line}),
 2032:               $csv_field->($message),
 2033:           ), "\n";
 2034:           close $fh;
 2035:       },
 2036:   );
 2037: 
 2038:   $logger->trace('application started');
 2039:   $logger->info('user logged in', { user => 'alice' });
 2040:   $logger->warn({ warning => 'disk usage above 80%' });
 2041: 
 2042: The resulting C<app_events.csv> looks like:
 2043: 
 2044:   timestamp,level,class,file,line,message
 2045:   "2026-05-27T14:00:00Z","trace","Log::Abstraction","app.pl","42","application started"
 2046:   "2026-05-27T14:00:01Z","info","Log::Abstraction","app.pl","43","user logged in"
 2047:   "2026-05-27T14:00:02Z","warn","Log::Abstraction","Log/Abstraction.pm","820","disk usage above 80%"
 2048: 
 2049: Note: C<class> is always C<Log::Abstraction> (or the subclass name if you subclass the
 2050: module).  For C<trace>, C<debug>, C<info>, and C<notice> calls, C<file> and C<line>
 2051: resolve to the caller's source location.  For C<warn> and C<error> calls the
 2052: extra C<_high_priority> stack frame shifts the resolution one level inward, so
 2053: C<file> and C<line> point into the module rather than the calling script.
 2054: 
 2055: For production use, consider replacing the manual C<$csv_field> quoting with
 2056: L<Text::CSV> for correct handling of embedded newlines and other edge cases.
 2057: 
 2058: If you also want real-time alerting on critical events, add the email logic
 2059: directly inside the code-ref callback -- test C<$args-E<gt>{level}> and call
 2060: your mailer for C<warn> / C<error> messages while still writing the CSV row
 2061: for every message.
 2062: 
 2063: Alternatively, use the C<sendmail> hash-ref backend on its own (without the
 2064: code-ref) and add a C<level> key to restrict emails to warn-and-above:
 2065: 
 2066:   my $logger = Log::Abstraction->new(
 2067:       level  => 'warn',
 2068:       logger => {
 2069:           sendmail => {
 2070:               host         => 'smtp.example.com',
 2071:               to           => 'ops@example.com',
 2072:               from         => 'logger@example.com',
 2073:               subject      => 'Application alert',
 2074:               level        => 'warn',   # only email at warn level and above
 2075:               min_interval => 300,      # at most one alert email per 5 minutes
 2076:           },
 2077:       },
 2078:   );
 2079: 
 2080: Note: the C<sendmail> backend writes the module's standard text format, not
 2081: CSV.  To produce CSV rows I<and> send email alerts from the same logger,
 2082: embed both the CSV-write and the mail-send logic inside a single code-ref
 2083: callback as described above.

 2085: =head1 LIMITATIONS
 2086: 
 2087: =over 4
 2088: 
 2089: =item B<Syslog hash mutation>
 2090: 
 2091: The C<syslog> sub-hash passed to C<new()> is mutated in-place on the first
 2092: log call: C<facility> and C<level> are temporarily removed before
 2093: C<setlogsock()> is called, then restored; C<server> is permanently renamed
 2094: to C<host>.  Sharing a syslog hashref between two C<Log::Abstraction>
 2095: instances is not supported and produces undefined behaviour on the second
 2096: instance.
 2097: 
 2098: =item B<trace is the same threshold as debug>
 2099: 
 2100: syslog has no priority below debug, so C<trace> and C<debug> share one
 2101: threshold: a logger at C<debug> level also emits C<trace> messages, and
 2102: C<trace> can't be filtered separately.
 2103: 
 2104: =item B<Unbounded message history by default>
 2105: 
 2106: Every logged message is kept in the history returned by L</messages>.  In a
 2107: long-running process (a daemon, or under mod_perl) set C<max_messages> to
 2108: stop it growing without bound.
 2109: 
 2110: =item B<syslog connection is shared>
 2111: 
 2112: C<openlog()> and C<closelog()> act on the whole process, so every instance
 2113: logging to syslog shares one connection, opened with the C<script_name> of
 2114: the first.  It is closed when the last such instance is destroyed.
 2115: 
 2116: =item B<No structured log fields>
 2117: 
 2118: All backends except the CODE-ref backend reduce the message to a flat string.
 2119: To log structured key/value pairs, use a CODE-ref backend that formats the
 2120: data itself.
 2121: 
 2122: =item B<Single-threaded email throttle>
 2123: 
 2124: The C<min_interval> throttle for the C<sendmail> backend and the
 2125: C<_syslog_opened> first-open flag are stored on the object without mutex
 2126: protection.  Under Perl ithreads or other concurrency models, objects shared
 2127: between threads are not safe.
 2128: 
 2129: =item B<OpenTelemetry not yet supported>
 2130: 
 2131: The OTel Logs SDK for Perl is incomplete; see the TODO block at the top of
 2132: F<lib/Log/Abstraction.pm> for a full status report and the list of blockers.
 2133: Monitor L<https://metacpan.org/pod/OpenTelemetry::SDK> for progress.
 2134: 
 2135: =item B<Log::Log4perl is a de-facto required dependency>
 2136: 
 2137: When no C<logger>, C<file>, or C<array> backend is configured, C<new()>
 2138: loads L<Log::Log4perl> and uses it as the default backend.  Although listed
 2139: as an optional runtime dependency, it is required in that default-backend
 2140: path.
