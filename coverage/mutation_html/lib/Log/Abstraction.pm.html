  216: =head1 DESCRIPTION
  217: 
  218: The C<Log::Abstraction> class provides a flexible logging layer on top of
  219: different types of loggers, including code references, arrays, file paths,
  220: and objects.  It also supports logging to syslog if configured.
  221: 
  222: =head2 Unicode
  223: 
  224: Messages may be character strings containing any Unicode text.  The file,
  225: fd and scalar-path backends write character strings as UTF-8 (unless an
  226: C<fd> handle already has a C<:utf8> or C<:encoding> layer, in which case the
  227: handle does the encoding), and C<format =E<gt> 'json'> output is UTF-8 too.
  228: journald fields are sent as UTF-8.  Byte strings are written unchanged.
  229: 
  230: =head2 Structured fields
  231: 
  232: Every logging method accepts a hash reference of structured fields after
  233: the message:
  234: 
  235:   $logger->info('User logged in', { user_id => 42, ip => $ip });
  236:   $logger->warn('Slow query', { ms => 1250 });
  237: 
  238: A hash reference is taken as fields only when it is the last of two or more
  239: arguments, so C<warn({ warning =E<gt> ... })> keeps its meaning, and a lone
  240: hash reference is still a message.  An empty hash reference is ignored.  The
  241: fields are copied, so changing the hash afterwards doesn't change what was
  242: logged.  They are kept out of the message and go to each backend as follows:
  243: 
  244: =over 4
  245: 
  246: =item * L</messages>, C<array> and an ARRAY C<logger> -- a C<fields> key in
  247: the entry, alongside C<level> and C<message>.
  248: 
  249: =item * a CODE C<logger> -- a C<fields> key in the hashref it is called with.
  250: 
  251: =item * C<format =E<gt> 'json'> -- a nested C<fields> object.  Objects are
  252: stringified; other references are kept as JSON data.
  253: 
  254: =item * C<journald> -- journal fields.  Each name is upper-cased, characters
  255: other than C<A-Z>, C<0-9> and C<_> become C<_>, leading underscores are
  256: removed and it is cut to 64 characters; a field left with no name is
  257: dropped.  Fields override the extra keys in the C<journald> hash, but never
  258: C<MESSAGE>, C<PRIORITY> or C<SYSLOG_IDENTIFIER>.
  259: 
  260: =item * text formats (C<file>, C<fd>, a scalar C<logger>), C<syslog>,
  261: C<sendmail> and object loggers -- appended to the message as logfmt-style
  262: C<key=value> pairs in key order, e.g. C<User logged in ip=10.0.0.1 user_id=42>.
  263: Characters other than C<[\w.-]> in a key become C<_>.  A value that is empty
  264: or contains white space, C<">, C<=> or C<\> is double-quoted, with C<"> and
  265: C<\> escaped and control characters written as C<\n>, C<\r>, C<\t> or
  266: C<\xNN>.  Objects are stringified and other references written as JSON.  An
  267: object logger is passed the pairs as an extra argument after the message.
  268: 
  269: =back
  270: 
  271: When logging through L<Log::Any>, a hash reference at the end of the call,
  272: together with the proxy's C<context>, arrives here as fields; see
  273: L<Log::Any::Adapter::Abstraction/structured>.

 2465: =head1 LIMITATIONS
 2466: 
 2467: =over 4
 2468: 
 2469: =item B<Syslog hash mutation>
 2470: 
 2471: The C<syslog> sub-hash passed to C<new()> is mutated in-place on the first
 2472: log call: C<facility> and C<level> are temporarily removed before
 2473: C<setlogsock()> is called, then restored; C<server> is permanently renamed
 2474: to C<host>.  Sharing a syslog hashref between two C<Log::Abstraction>
 2475: instances is not supported and produces undefined behaviour on the second
 2476: instance.
 2477: 
 2478: =item B<trace is the same threshold as debug>
 2479: 
 2480: syslog has no priority below debug, so C<trace> and C<debug> share one
 2481: threshold: a logger at C<debug> level also emits C<trace> messages, and
 2482: C<trace> can't be filtered separately.
 2483: 
 2484: =item B<Unbounded message history by default>
 2485: 
 2486: Every logged message is kept in the history returned by L</messages>.  In a
 2487: long-running process (a daemon, or under mod_perl) set C<max_messages> to
 2488: stop it growing without bound.
 2489: 
 2490: =item B<syslog connection is shared>
 2491: 
 2492: C<openlog()> and C<closelog()> act on the whole process, so every instance
 2493: logging to syslog shares one connection, opened with the C<script_name> of
 2494: the first.  It is closed when the last such instance is destroyed.
 2495: 
 2496: =item B<Structured fields are text in most backends>
 2497: 
 2498: Only the history, array, CODE-ref, JSON and journald backends keep
 2499: L</Structured fields> as data.  Text formats, syslog, email and object
 2500: loggers get them as C<key=value> text appended to the message, and a custom
 2501: C<format> has no token for them on their own.
 2502: 
 2503: =item B<Single-threaded email throttle>
 2504: 
 2505: The C<min_interval> throttle for the C<sendmail> backend and the
 2506: C<_syslog_opened> first-open flag are stored on the object without mutex
 2507: protection.  Under Perl ithreads or other concurrency models, objects shared
 2508: between threads are not safe.
 2509: 
 2510: =item B<OpenTelemetry not yet supported>
 2511: 
 2512: The OTel Logs SDK for Perl is incomplete; see the TODO block at the top of
 2513: F<lib/Log/Abstraction.pm> for a full status report and the list of blockers.
 2514: Monitor L<https://metacpan.org/pod/OpenTelemetry::SDK> for progress.
 2515: 
 2516: =item B<Log::Log4perl is a de-facto required dependency>
 2517: 
 2518: When no C<logger>, C<file>, or C<array> backend is configured, C<new()>
 2519: loads L<Log::Log4perl> and uses it as the default backend.  Although listed
 2520: as an optional runtime dependency, it is required in that default-backend
 2521: path.
