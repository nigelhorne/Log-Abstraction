 1350: =head2 CSV file logging for BI import
 1351: 
 1352: The code-reference backend gives you full control over the output format.
 1353: The example below writes every message at C<trace> level and above as a
 1354: CSV row to a file, producing output that can be loaded directly into a
 1355: spreadsheet or BI tool (Tableau, Power BI, Metabase, etc.).
 1356: 
 1357: Each row contains: C<timestamp>, C<level>, C<class>, C<file>, C<line>, C<message>.
 1358: 
 1359:   use Log::Abstraction;
 1360: 
 1361:   my $csv_file = 'app_events.csv';
 1362: 
 1363:   # Write the header row once (skip if the file already exists and has data).
 1364:   unless (-s $csv_file) {
 1365:       open my $fh, '>', $csv_file or die "Cannot open $csv_file: $!";
 1366:       print $fh qq{timestamp,level,class,file,line,message\n};
 1367:       close $fh;
 1368:   }
 1369: 
 1370:   # Helper: quote a single CSV field (escapes embedded double-quotes).
 1371:   my $csv_field = sub {
 1372:       my $v = defined $_[0] ? $_[0] : '';
 1373:       $v =~ s/"/""/g;
 1374:       return qq{"$v"};
 1375:   };
 1376: 
 1377:   my $logger = Log::Abstraction->new(
 1378:       level  => 'trace',        # capture everything from trace upwards
 1379:       logger => sub {
 1380:           my $args = $_[0];
 1381: 
 1382:           my $timestamp = POSIX::strftime('%Y-%m-%dT%H:%M:%SZ', gmtime);
 1383:           my $message  = join(' ', @{ $args->{message} // [] });
 1384: 
 1385:           open my $fh, '>>', $csv_file or return;
 1386:           print $fh join(',',
 1387:               $csv_field->($timestamp),
 1388:               $csv_field->($args->{level}),
 1389:               $csv_field->($args->{class}),
 1390:               $csv_field->($args->{file}),
 1391:               $csv_field->($args->{line}),
 1392:               $csv_field->($message),
 1393:           ), "\n";
 1394:           close $fh;
 1395:       },
 1396:   );
 1397: 
 1398:   $logger->trace('application started');
 1399:   $logger->info('user logged in', { user => 'alice' });
 1400:   $logger->warn({ warning => 'disk usage above 80%' });
 1401: 
 1402: The resulting C<app_events.csv> looks like:
 1403: 
 1404:   timestamp,level,class,file,line,message
 1405:   "2026-05-27T14:00:00Z","trace","Log::Abstraction","app.pl","42","application started"
 1406:   "2026-05-27T14:00:01Z","info","Log::Abstraction","app.pl","43","user logged in"
 1407:   "2026-05-27T14:00:02Z","warn","Log::Abstraction","Log/Abstraction.pm","820","disk usage above 80%"
 1408: 
 1409: Note: C<class> is always C<Log::Abstraction> (or the subclass name if you subclass the
 1410: module).  For C<trace>, C<debug>, C<info>, and C<notice> calls, C<file> and C<line>
 1411: resolve to the caller's source location.  For C<warn> and C<error> calls the
 1412: extra C<_high_priority> stack frame shifts the resolution one level inward, so
 1413: C<file> and C<line> point into the module rather than the calling script.
 1414: 
 1415: For production use, consider replacing the manual C<$csv_field> quoting with
 1416: L<Text::CSV> for correct handling of embedded newlines and other edge cases.
 1417: 
 1418: If you also want real-time alerting on critical events, add the email logic
 1419: directly inside the code-ref callback -- test C<$args-E<gt>{level}> and call
 1420: your mailer for C<warn> / C<error> messages while still writing the CSV row
 1421: for every message.
 1422: 
 1423: Alternatively, use the C<sendmail> hash-ref backend on its own (without the
 1424: code-ref) and add a C<level> key to restrict emails to warn-and-above:
 1425: 
 1426:   my $logger = Log::Abstraction->new(
 1427:       level  => 'warn',
 1428:       logger => {
 1429:           sendmail => {
 1430:               host         => 'smtp.example.com',
 1431:               to           => 'ops@example.com',
 1432:               from         => 'logger@example.com',
 1433:               subject      => 'Application alert',
 1434:               level        => 'warn',   # only email at warn level and above
 1435:               min_interval => 300,      # at most one alert email per 5 minutes
 1436:           },
 1437:       },
 1438:   );
 1439: 
 1440: Note: the C<sendmail> backend writes the module's standard text format, not
 1441: CSV.  To produce CSV rows I<and> send email alerts from the same logger,
 1442: embed both the CSV-write and the mail-send logic inside a single code-ref
