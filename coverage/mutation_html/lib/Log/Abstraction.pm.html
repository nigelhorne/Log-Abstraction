 1517: CSV row to a file, producing output that can be loaded directly into a
 1518: spreadsheet or BI tool (Tableau, Power BI, Metabase, etc.).
 1519: 
 1520: Each row contains: C<timestamp>, C<level>, C<class>, C<file>, C<line>, C<message>.
 1521: 
 1522:   use Log::Abstraction;
 1523: 
 1524:   my $csv_file = 'app_events.csv';
 1525: 
 1526:   # Write the header row once (skip if the file already exists and has data).
 1527:   unless (-s $csv_file) {
 1528:       open my $fh, '>', $csv_file or die "Cannot open $csv_file: $!";
 1529:       print $fh qq{timestamp,level,class,file,line,message\n};
 1530:       close $fh;
 1531:   }
 1532: 
 1533:   # Helper: quote a single CSV field (escapes embedded double-quotes).
 1534:   my $csv_field = sub {
 1535:       my $v = defined $_[0] ? $_[0] : '';
 1536:       $v =~ s/"/""/g;
 1537:       return qq{"$v"};
 1538:   };
 1539: 
 1540:   my $logger = Log::Abstraction->new(
 1541:       level  => 'trace',        # capture everything from trace upwards
 1542:       logger => sub {
 1543:           my $args = $_[0];
 1544: 
 1545:           my $timestamp = POSIX::strftime('%Y-%m-%dT%H:%M:%SZ', gmtime);
 1546:           my $message  = join(' ', @{ $args->{message} // [] });
 1547: 
 1548:           open my $fh, '>>', $csv_file or return;
 1549:           print $fh join(',',
 1550:               $csv_field->($timestamp),
 1551:               $csv_field->($args->{level}),
 1552:               $csv_field->($args->{class}),
 1553:               $csv_field->($args->{file}),
 1554:               $csv_field->($args->{line}),
 1555:               $csv_field->($message),
 1556:           ), "\n";
 1557:           close $fh;
 1558:       },
 1559:   );
 1560: 
 1561:   $logger->trace('application started');
 1562:   $logger->info('user logged in', { user => 'alice' });
 1563:   $logger->warn({ warning => 'disk usage above 80%' });
 1564: 
 1565: The resulting C<app_events.csv> looks like:
 1566: 
 1567:   timestamp,level,class,file,line,message
 1568:   "2026-05-27T14:00:00Z","trace","Log::Abstraction","app.pl","42","application started"
 1569:   "2026-05-27T14:00:01Z","info","Log::Abstraction","app.pl","43","user logged in"
 1570:   "2026-05-27T14:00:02Z","warn","Log::Abstraction","Log/Abstraction.pm","820","disk usage above 80%"
 1571: 
 1572: Note: C<class> is always C<Log::Abstraction> (or the subclass name if you subclass the
 1573: module).  For C<trace>, C<debug>, C<info>, and C<notice> calls, C<file> and C<line>
 1574: resolve to the caller's source location.  For C<warn> and C<error> calls the
 1575: extra C<_high_priority> stack frame shifts the resolution one level inward, so
 1576: C<file> and C<line> point into the module rather than the calling script.
 1577: 
 1578: For production use, consider replacing the manual C<$csv_field> quoting with
 1579: L<Text::CSV> for correct handling of embedded newlines and other edge cases.
 1580: 
 1581: If you also want real-time alerting on critical events, add the email logic
 1582: directly inside the code-ref callback -- test C<$args-E<gt>{level}> and call
 1583: your mailer for C<warn> / C<error> messages while still writing the CSV row
 1584: for every message.
 1585: 
 1586: Alternatively, use the C<sendmail> hash-ref backend on its own (without the
 1587: code-ref) and add a C<level> key to restrict emails to warn-and-above:
 1588: 
 1589:   my $logger = Log::Abstraction->new(
 1590:       level  => 'warn',
 1591:       logger => {
 1592:           sendmail => {
 1593:               host         => 'smtp.example.com',
 1594:               to           => 'ops@example.com',
 1595:               from         => 'logger@example.com',
 1596:               subject      => 'Application alert',
 1597:               level        => 'warn',   # only email at warn level and above
 1598:               min_interval => 300,      # at most one alert email per 5 minutes
 1599:           },
 1600:       },
 1601:   );
 1602: 
 1603: Note: the C<sendmail> backend writes the module's standard text format, not
 1604: CSV.  To produce CSV rows I<and> send email alerts from the same logger,
 1605: embed both the CSV-write and the mail-send logic inside a single code-ref
 1606: callback as described above.
