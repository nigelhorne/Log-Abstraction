 1637: =head2 CSV file logging for BI import
 1638: 
 1639: The code-reference backend gives you full control over the output format.
 1640: The example below writes every message at C<trace> level and above as a
 1641: CSV row to a file, producing output that can be loaded directly into a
 1642: spreadsheet or BI tool (Tableau, Power BI, Metabase, etc.).
 1643: 
 1644: Each row contains: C<timestamp>, C<level>, C<class>, C<file>, C<line>, C<message>.
 1645: 
 1646:   use Log::Abstraction;
 1647: 
 1648:   my $csv_file = 'app_events.csv';
 1649: 
 1650:   # Write the header row once (skip if the file already exists and has data).
 1651:   unless (-s $csv_file) {
 1652:       open my $fh, '>', $csv_file or die "Cannot open $csv_file: $!";
 1653:       print $fh qq{timestamp,level,class,file,line,message\n};
 1654:       close $fh;
 1655:   }
 1656: 
 1657:   # Helper: quote a single CSV field (escapes embedded double-quotes).
 1658:   my $csv_field = sub {
 1659:       my $v = defined $_[0] ? $_[0] : '';
 1660:       $v =~ s/"/""/g;
 1661:       return qq{"$v"};
 1662:   };
 1663: 
 1664:   my $logger = Log::Abstraction->new(
 1665:       level  => 'trace',        # capture everything from trace upwards
 1666:       logger => sub {
 1667:           my $args = $_[0];
 1668: 
 1669:           my $timestamp = POSIX::strftime('%Y-%m-%dT%H:%M:%SZ', gmtime);
 1670:           my $message  = join(' ', @{ $args->{message} // [] });
 1671: 
 1672:           open my $fh, '>>', $csv_file or return;
 1673:           print $fh join(',',
 1674:               $csv_field->($timestamp),
 1675:               $csv_field->($args->{level}),
 1676:               $csv_field->($args->{class}),
 1677:               $csv_field->($args->{file}),
 1678:               $csv_field->($args->{line}),
 1679:               $csv_field->($message),
 1680:           ), "\n";
 1681:           close $fh;
 1682:       },
 1683:   );
 1684: 
 1685:   $logger->trace('application started');
 1686:   $logger->info('user logged in', { user => 'alice' });
 1687:   $logger->warn({ warning => 'disk usage above 80%' });
 1688: 
 1689: The resulting C<app_events.csv> looks like:
 1690: 
 1691:   timestamp,level,class,file,line,message
 1692:   "2026-05-27T14:00:00Z","trace","Log::Abstraction","app.pl","42","application started"
 1693:   "2026-05-27T14:00:01Z","info","Log::Abstraction","app.pl","43","user logged in"
 1694:   "2026-05-27T14:00:02Z","warn","Log::Abstraction","Log/Abstraction.pm","820","disk usage above 80%"
 1695: 
 1696: Note: C<class> is always C<Log::Abstraction> (or the subclass name if you subclass the
 1697: module).  For C<trace>, C<debug>, C<info>, and C<notice> calls, C<file> and C<line>
 1698: resolve to the caller's source location.  For C<warn> and C<error> calls the
 1699: extra C<_high_priority> stack frame shifts the resolution one level inward, so
 1700: C<file> and C<line> point into the module rather than the calling script.
 1701: 
 1702: For production use, consider replacing the manual C<$csv_field> quoting with
 1703: L<Text::CSV> for correct handling of embedded newlines and other edge cases.
 1704: 
 1705: If you also want real-time alerting on critical events, add the email logic
 1706: directly inside the code-ref callback -- test C<$args-E<gt>{level}> and call
 1707: your mailer for C<warn> / C<error> messages while still writing the CSV row
 1708: for every message.
 1709:

 1712: 
 1713:   my $logger = Log::Abstraction->new(
 1714:       level  => 'warn',
 1715:       logger => {
 1716:           sendmail => {
 1717:               host         => 'smtp.example.com',
 1718:               to           => 'ops@example.com',
 1719:               from         => 'logger@example.com',
 1720:               subject      => 'Application alert',
 1721:               level        => 'warn',   # only email at warn level and above
 1722:               min_interval => 300,      # at most one alert email per 5 minutes
 1723:           },
 1724:       },
 1725:   );
 1726:

 1728: CSV.  To produce CSV rows I<and> send email alerts from the same logger,
 1729: embed both the CSV-write and the mail-send logic inside a single code-ref
 1730: callback as described above.
