  212: =head1 SYNOPSIS
  213: 
  214:   use Log::Abstraction;
  215: 
  216:   my $logger = Log::Abstraction->new(logger => 'logfile.log');
  217: 
  218:   $logger->debug('This is a debug message');
  219:   $logger->info('This is an info message');
  220:   $logger->notice('This is a notice message');
  221:   $logger->trace('This is a trace message');
  222:   $logger->warn({ warning => 'This is a warning message' });
  223: 
  224:   # Structured fields
  225:   $logger->info('User logged in', { user_id => 42 });
  226: 
  227: =head1 DESCRIPTION
  228: 
  229: The C<Log::Abstraction> class provides a flexible logging layer on top of
  230: different types of loggers, including code references, arrays, file paths,
  231: and objects.  It also supports logging to syslog if configured.
  232: 
  233: =head2 Unicode
  234: 
  235: Messages may be character strings containing any Unicode text.  The file,
  236: fd and scalar-path backends write character strings as UTF-8 (unless an
  237: C<fd> handle already has a C<:utf8> or C<:encoding> layer, in which case the
  238: handle does the encoding), and C<format =E<gt> 'json'> output is UTF-8 too.
  239: journald fields are sent as UTF-8.  Byte strings are written unchanged.
  240: 
  241: =head2 Structured fields
  242: 
  243: Every logging method accepts a hash reference of structured fields after
  244: the message:
  245: 
  246:   $logger->info('User logged in', { user_id => 42, ip => $ip });
  247:   $logger->warn('Slow query', { ms => 1250 });
  248: 
  249: A hash reference is taken as fields only when it is the last of two or more
  250: arguments, so C<warn({ warning =E<gt> ... })> keeps its meaning, and a lone
  251: hash reference is still a message.  An empty hash reference is ignored.  The
  252: fields are copied, so changing the hash afterwards doesn't change what was
  253: logged.  They are kept out of the message and go to each backend as follows:
  254: 
  255: =over 4
  256: 
  257: =item * L</messages>, C<array> and an ARRAY C<logger> -- a C<fields> key in
  258: the entry, alongside C<level> and C<message>.
  259: 
  260: =item * a CODE C<logger> -- a C<fields> key in the hashref it is called with.
  261: 
  262: =item * C<format =E<gt> 'json'> -- a nested C<fields> object.  Objects are
  263: stringified; other references are kept as JSON data.
  264: 
  265: =item * C<journald> -- journal fields.  Each name is upper-cased, characters
  266: other than C<A-Z>, C<0-9> and C<_> become C<_>, leading underscores are
  267: removed and it is cut to 64 characters; a field left with no name is
  268: dropped.  Fields override the extra keys in the C<journald> hash, but never
  269: C<MESSAGE>, C<PRIORITY> or C<SYSLOG_IDENTIFIER>.
  270: 
  271: =item * text formats (C<file>, C<fd>, a scalar C<logger>), C<syslog>,
  272: C<sendmail> and object loggers -- appended to the message as logfmt-style
  273: C<key=value> pairs in key order, e.g. C<User logged in ip=10.0.0.1 user_id=42>.
  274: Characters other than C<[\w.-]> in a key become C<_>.  A value that is empty
  275: or contains white space, C<">, C<=> or C<\> is double-quoted, with C<"> and
  276: C<\> escaped and control characters written as C<\n>, C<\r>, C<\t> or
  277: C<\xNN>.  Objects are stringified and other references written as JSON.  An
  278: object logger is passed the pairs as an extra argument after the message.
  279: 
  280: =back
  281: 
  282: When logging through L<Log::Any>, a hash reference at the end of the call,
  283: together with the proxy's C<context>, arrives here as fields; see
  284: L<Log::Any::Adapter::Abstraction/structured>.
  285: 
  286: =head1 METHODS
  287: 
  288: =head2 new
  289: 
  290:   my $logger = Log::Abstraction->new(%args);
  291:   my $logger = Log::Abstraction->new(\%args);
  292:   my $logger = Log::Abstraction->new($file_path);
  293: 
  294:   # Clone with optional overrides
  295:   my $clone = $logger->new(level => 'debug');
  296: 
  297: Creates a new C<Log::Abstraction> instance, or clones an existing one when
  298: called on an object.  It may also be called as a plain function,
  299: C<Log::Abstraction::new(%args)>, which behaves like
  300: C<Log::Abstraction-E<gt>new(%args)>.
  301: 
  302: =head3 Arguments
  303: 
  304: =over 4
  305: 
  306: =item * C<carp_on_warn>
  307: 
  308: If set to 1, and no C<logger> is given, call C<Carp::carp> on C<warn()>.
  309: Also causes C<error()> to C<carp> if C<croak_on_error> is not set.
  310: 
  311: =item * C<croak_on_error>
  312: 
  313: If set to 1, and no C<logger> is given, call C<Carp::croak> on C<error()>.
  314: 
  315: =item * C<config_file>
  316: 
  317: Path to a configuration file (YAML, XML, INI, etc.) whose contents are
  318: merged with the constructor arguments.  On non-Windows systems the class
  319: can also be configured via environment variables prefixed with
  320: C<"Log::Abstraction::">.  For example:
  321: 
  322:   export Log::Abstraction::script_name=foo
  323: 
  324: =item * C<ctx>
  325: 
  326: Arbitrary context value passed through to CODE-ref logger callbacks as
  327: C<$args-E<gt>{ctx}>.
  328: 
  329: =item * C<format>
  330: 
  331: Format string for file/fd backends.  Tokens expanded at log time:
  332: 
  333:   %callstack%   caller file and line number
  334:   %class%       blessed class of the logger object
  335:   %level%       upper-cased level name
  336:   %message%     the joined log message
  337:   %timestamp%   the time of the call; YYYY-MM-DD HH:MM:SS local time by
  338:                 default (see timestamp_format, timestamp_precision and utc)
  339:   %env_FOO%     value of $ENV{FOO}, or empty string if unset
  340: 
  341: Tokens are only expanded in the format string itself, never in the text
  342: of the message.  Each line break in a message is followed by a tab, so a
  343: continuation line can't be mistaken for a new log entry.
  344: 
  345: The special value C<"json"> (not a format string but a magic keyword) switches
  346: all file and fd backends to emit one compact JSON object per log line:
  347: 
  348:   {"timestamp":"...","level":"info","message":"...","file":"...","line":42}
  349: 
  350: This format is compatible with log aggregators such as journald, Loki,
  351: Elasticsearch, and Splunk.  C<class> is included when the logger is a subclass
  352: of C<Log::Abstraction>, and C<fields> when the call has L</Structured fields>.
  353: Keys are emitted in sorted order.
  354: 
  355: B<Security note:> because C<format> may contain C<%env_*%> tokens, avoid
  356: granting untrusted sources write access to config files that set this key.
  357: 
  358: =item * C<level>
  359: 
  360: Minimum level at which to emit log entries.  Defaults to C<"warning">.
  361: Valid values (case-insensitive): C<trace>, C<debug>, C<info>/C<informational>,
  362: C<notice>, C<warn>/C<warning>, C<error>/C<err>, C<crit>/C<critical>/C<fatal>,
  363: C<alert>, C<emerg>/C<emergency>/C<panic>.  C<trace> and C<debug> are the same
  364: threshold (see L</LIMITATIONS>).
  365: 
  366: =item * C<max_messages>
  367: 
  368: The most entries to keep in the in-memory history returned by
  369: L</messages>; when it is full, the oldest entry is discarded.  Must be a
  370: non-negative integer.  Unlimited by default, which in a long-running process
  371: means the history grows without bound.
  372: 
  373: =item * C<logger>
  374: 
  375: One of:
  376: 
  377: =over 4
  378: 
  379: =item * A code reference -- called with a hashref C<{ class, file, line, level, message, ctx, fields }>
  380: (C<ctx> and C<fields> only when there are any)
  381: 
  382: =item * An object -- method matching the level name is called on it
  383: 
  384: =item * A hash reference -- may contain C<file>, C<array>, C<fd>, C<syslog>, C<journald>, and/or C<sendmail> keys
  385: 
  386: =item * An array reference -- C<{ level, message }> hashrefs are pushed onto it, with a
  387: C<fields> key when the call has L</Structured fields>
  388: 
  389: =item * A scalar string -- treated as a file path to append to
  390: 
  391: =back
  392: 
  393: When not supplied, L<Log::Log4perl> is initialised as the default backend.
  394: 
  395: The C<sendmail> sub-hash supports:
  396: C<host>, C<port>, C<to>, C<from>, C<subject>, C<level>, C<min_interval>.
  397: C<to> is required.  C<level> may be a level name or a syslog number (0-7);
  398: without it, every message is emailed.
  399: At most one email is sent per C<min_interval> seconds per instance.  If
  400: delivery fails, C<Carp::carp> is called and the other backends still receive
  401: the message.
  402: 
  403: The C<syslog> sub-hash supports:
  404: 
  405: =over 4
  406: 
  407: =item * C<facility> -- the syslog facility (default: C<local0>)
  408: 
  409: =item * C<level> -- only messages at this level or more severe are sent; a level name or a syslog number (0-7)
  410: 
  411: =item * C<host> (or its alias C<server>), and any other L<Sys::Syslog/setlogsock> option -- passed to C<setlogsock()>
  412: 
  413: =back
  414: 
  415: The C<journald> sub-hash sends each message as a single datagram to the
  416: systemd journal using the journald native protocol.  Supported keys:
  417: 
  418: =over 4
  419: 
  420: =item * C<socket> -- path to the journald socket (default: F</run/systemd/journal/socket>)
  421: 
  422: =item * C<identifier> -- value for the C<SYSLOG_IDENTIFIER> field (default: basename of C<$0>)
  423: 
  424: =item * any other key -- included verbatim as an uppercase journald field name.
  425: The upper-cased name must contain only C<A-Z>, C<0-9> and C<_>, and must not
  426: start with C<_>; C<new()> croaks otherwise.
  427: 
  428: =back
  429: 
  430: The C<PRIORITY> field is set automatically from the log level (0=emerg...7=debug).
  431: A message too large for one datagram (about 200KB) is truncated and
  432: C<[truncated]> appended.
  433: Delivery failures are silent apart from a single C<Carp::carp> (repeated only
  434: after a later send has succeeded); the application is never crashed by a
  435: journald error.
  436: 
  437: =item * C<script_name>
  438: 
  439: Script name reported to syslog.  Auto-detected from C<$0> if not supplied.
  440: 
  441: =item * C<timestamp_format>
  442: 
  443: How C<%timestamp%>, and the C<timestamp> key of C<format =E<gt> 'json'>,
  444: are written.  Either a L<POSIX/strftime> pattern (default
  445: C<%Y-%m-%d %H:%M:%S>) or one of these names (case-insensitive):
  446: 
  447:   iso8601, rfc3339   2026-10-03T20:14:23-04:00, or 2026-10-04T00:14:23Z with utc
  448: 
  449: The pattern may also use:
  450: 
  451:   %N        fractional seconds, 9 digits (nanoseconds)
  452:   %3N       fractional seconds, 3 digits (milliseconds); any width 1-9
  453:   %z        UTC offset as +hhmm (on every platform, unlike some strftimes)
  454:   %:z       UTC offset as +hh:mm, as RFC 3339 needs
  455:   %Z        the time-zone name; "UTC" when utc is set
  456:   %%        a literal %
  457: 
  458: Fractional seconds come from L<Time::HiRes> and are truncated, not rounded;
  459: digits beyond the system clock's resolution (usually microseconds) are
  460: noise.  The timestamp is taken once per message, so every backend shows the
  461: same time.
  462: 
  463: =item * C<timestamp_precision>
  464: 
  465: The number of fractional-second digits, 0-9 (default 0), added after the
  466: seconds (each C<%S>) of whichever C<timestamp_format> is in use:
  467: 
  468:   Log::Abstraction->new(timestamp_format => 'rfc3339', timestamp_precision => 3, utc => 1);
  469:   # 2026-10-04T00:14:24.094Z
  470: 
  471: =item * C<utc>
  472: 
  473: If true, timestamps are in UTC rather than local time.
  474: 
  475: =item * C<verbose>
  476: 
  477: When using the default Log::Log4perl backend, raises the logging level to
  478: DEBUG when set to a true value.
  479: 
  480: =back

 2531: =head2 CSV file logging for BI import
 2532: 
 2533: The code-reference backend gives you full control over the output format.
 2534: The example below writes every message at C<trace> level and above as a
 2535: CSV row to a file, producing output that can be loaded directly into a
 2536: spreadsheet or BI tool (Tableau, Power BI, Metabase, etc.).
 2537: 
 2538: Each row contains: C<timestamp>, C<level>, C<class>, C<file>, C<line>, C<message>.
 2539: 
 2540:   use Log::Abstraction;
 2541: 
 2542:   my $csv_file = 'app_events.csv';
 2543: 
 2544:   # Write the header row once (skip if the file already exists and has data).
 2545:   unless (-s $csv_file) {
 2546:       open my $fh, '>', $csv_file or die "Cannot open $csv_file: $!";
 2547:       print $fh qq{timestamp,level,class,file,line,message\n};
 2548:       close $fh;
 2549:   }
 2550: 
 2551:   # Helper: quote a single CSV field (escapes embedded double-quotes).
 2552:   my $csv_field = sub {
 2553:       my $v = defined $_[0] ? $_[0] : '';
 2554:       $v =~ s/"/""/g;
 2555:       return qq{"$v"};
 2556:   };
 2557: 
 2558:   my $logger = Log::Abstraction->new(
 2559:       level  => 'trace',        # capture everything from trace upwards
 2560:       logger => sub {
 2561:           my $args = $_[0];
 2562: 
 2563:           my $timestamp = POSIX::strftime('%Y-%m-%dT%H:%M:%SZ', gmtime);
 2564:           my $message  = join(' ', @{ $args->{message} // [] });
 2565: 
 2566:           open my $fh, '>>', $csv_file or return;
 2567:           print $fh join(',',
 2568:               $csv_field->($timestamp),
 2569:               $csv_field->($args->{level}),
 2570:               $csv_field->($args->{class}),
 2571:               $csv_field->($args->{file}),
 2572:               $csv_field->($args->{line}),
 2573:               $csv_field->($message),
 2574:           ), "\n";
 2575:           close $fh;
 2576:       },
 2577:   );
 2578: 
 2579:   $logger->trace('application started');
 2580:   $logger->info('user logged in', { user => 'alice' });
 2581:   $logger->warn({ warning => 'disk usage above 80%' });

 2584: 
 2585:   timestamp,level,class,file,line,message
 2586:   "2026-05-27T14:00:00Z","trace","Log::Abstraction","app.pl","42","application started"
 2587:   "2026-05-27T14:00:01Z","info","Log::Abstraction","app.pl","43","user logged in"
 2588:   "2026-05-27T14:00:02Z","warn","Log::Abstraction","Log/Abstraction.pm","820","disk usage above 80%"

 2594: C<file> and C<line> point into the module rather than the calling script.

 2597: L<Text::CSV> for correct handling of embedded newlines and other edge cases.

 2626: =head1 LIMITATIONS
 2627: 
 2628: =over 4
 2629: 
 2630: =item B<Syslog hash mutation>
 2631: 
 2632: The C<syslog> sub-hash passed to C<new()> is mutated in-place on the first
 2633: log call: C<facility> and C<level> are temporarily removed before
 2634: C<setlogsock()> is called, then restored; C<server> is permanently renamed
 2635: to C<host>.  Sharing a syslog hashref between two C<Log::Abstraction>
 2636: instances is not supported and produces undefined behaviour on the second
 2637: instance.
 2638: 
 2639: =item B<trace is the same threshold as debug>
 2640: 
 2641: syslog has no priority below debug, so C<trace> and C<debug> share one
 2642: threshold: a logger at C<debug> level also emits C<trace> messages, and
 2643: C<trace> can't be filtered separately.
 2644: 
 2645: =item B<Unbounded message history by default>
 2646: 
 2647: Every logged message is kept in the history returned by L</messages>.  In a
 2648: long-running process (a daemon, or under mod_perl) set C<max_messages> to
 2649: stop it growing without bound.
 2650: 
 2651: =item B<syslog connection is shared>
 2652: 
 2653: C<openlog()> and C<closelog()> act on the whole process, so every instance
 2654: logging to syslog shares one connection, opened with the C<script_name> of
 2655: the first.  It is closed when the last such instance is destroyed.
 2656: 
 2657: =item B<Structured fields are text in most backends>
 2658: 
 2659: Only the history, array, CODE-ref, JSON and journald backends keep
 2660: L</Structured fields> as data.  Text formats, syslog, email and object
 2661: loggers get them as C<key=value> text appended to the message, and a custom
 2662: C<format> has no token for them on their own.
 2663: 
 2664: =item B<Single-threaded email throttle>
 2665: 
 2666: The C<min_interval> throttle for the C<sendmail> backend and the
 2667: C<_syslog_opened> first-open flag are stored on the object without mutex
 2668: protection.  Under Perl ithreads or other concurrency models, objects shared
 2669: between threads are not safe.
 2670: 
 2671: =item B<OpenTelemetry not yet supported>
 2672: 
 2673: The OTel Logs SDK for Perl is incomplete; see the TODO block at the top of
 2674: F<lib/Log/Abstraction.pm> for a full status report and the list of blockers.
 2675: Monitor L<https://metacpan.org/pod/OpenTelemetry::SDK> for progress.
 2676: 
 2677: =item B<Log::Log4perl is a de-facto required dependency>
 2678: 
 2679: When no C<logger>, C<file>, or C<array> backend is configured, C<new()>
 2680: loads L<Log::Log4perl> and uses it as the default backend.  Although listed
 2681: as an optional runtime dependency, it is required in that default-backend
 2682: path.
