=head1 NAME

Log::Abstraction::Backend::Journald - send messages to the systemd journal

=head1 VERSION

0.40

=head1 DESCRIPTION

Built for the C<journald> key of a C<logger> hash.  Each message is one
datagram in the journald native protocol
(L<https://systemd.io/JOURNAL_NATIVE_PROTOCOL/>), with the fields
C<MESSAGE> (with a C<format>, the formatted line), C<PRIORITY>,
C<SYSLOG_IDENTIFIER>, the hash's other keys upper-cased, and the structured
fields.  A message too big for one datagram is truncated.  A failed send
carps, once until a send succeeds again.  The socket is opened for the
first message and reused for the next ones, until a send fails.

For use by L<Log::Abstraction> only; see L<Log::Abstraction::Backend>.

136# Purpose:      Format key=value fields in the journald native protocol and

138# Entry:        $self        -- the backend, which keeps the socket in
139#                              $self->{_socket} between messages.
140#               $socket_path -- filesystem path of the journald socket.
141#               %fields      -- FIELD_NAME => value pairs; names must be
142#                              uppercase ASCII + digits + underscore.
143# Exit:         Returns nothing.  Croaks on socket or send failure (the caller
144#               wraps every call in eval{} so failures are silent to the app).
145# Side effects: Opens a Unix datagram socket on the first call, and keeps it
146#               for the next; closes it after a failed send, so that the
147#               next message gets a new one.
148# Notes:        Values containing newline or NUL use the binary framing
149#               (field-name NL uint64-LE-length value NL) as specified by
